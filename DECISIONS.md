# OPEX+ prototype decision log

Statuses: **CONFIRMED** (stated by the user or a source document), **PROPOSED** (a labelled default
built so the demonstration can proceed) and **OPEN** (unresolved business decision). The SRS
(`docs/srs/Felix_ERP_SRS_v2_Multi_Tenant.md`) and the architecture specification are the source of
truth. A decision recorded in the live issue tracker supersedes a PROPOSED default here.

The first five sections are carried unchanged, with ids added (C, P, O), from the legacy
prototype's `PROTOTYPE_DECISIONS.md` (the directory `felix-erp-prototype/` was removed after commit
`0b4283e`; a byte-identical copy is `opex-prototype/tests/fixtures/legacy-decisions.md`); the rebuild

## CONFIRMED requirements (carried from the legacy prototype)

- **C1** Tenant is a customer company, never a factory. Felix has FLX-926 and FLX-927; Demo Apparel has an independent factory. Tenant-owned records carry `tenantId` and normalized relational IDs.
- **C2** Normal sessions resolve tenant through an active membership. Tenant/factory/section/SectionShift/own-assignment queries and mutation validation use central helpers. Platform directory access is separate; privileged tenant entry is visible and audited.
- **C3** WHAT permissions and WHERE membership scope remain separate. User accounts and employees remain separate.
- **C4** ProductionDay is canonical, uniquely identified by tenant + line + shift + date. HourlyOutput children supply totals; blank is `null`, while zero is a populated running hour. No independently entered daily total exists.
- **C5** ProductionEvent is the only lost-time source. Staffing links canonical attendance and supplements effective assignment responsibility.
- **C6** Efficiency uses present operators + helpers + manual staff. Efficiency hit rate is actual / planned × 100. Aggregation uses total earned SAH over available manpower hours. Zero/missing denominators display unavailable readings.
- **C7** One AttendanceRecord register supplies timesheets and scores. Corrections retain before/after values and reasons. Overnight clocks are handled by adding the next-day boundary.
- **C8** Production workflow is Draft → Pending → Approved or Pending → Returned → Draft. Appended workflow events retain actor, timestamp and reason. Approved records cannot be ordinarily edited or removed.
- **C9** Approval captures style SMV for historical calculations. New audit events snapshot organization context; access to a transfer's payload requires scope over both its before and after contexts.
- **C10** Default scores use efficiency 40, defect 20, first hour 20, QCO 10, attendance 10; components cap at 100. Missing components drop out and their weights renormalize. Factory targets override tenant defaults. Snapshots store config, targets, assignment context and component results.
- **C11** Buyer is normalized. Orders reference styles through order lines. Working calendars configure weekly non-working days and explicit exceptions. Capacity captures SMV, required minutes, operator count, efficiency and daily capacity assumptions.
- **C12** Stock on hand derives only from StockMovement. Posted receipts generate accepted-quantity movements. Reversal adds opposite entries and preserves the receipt history. Invoice balances derive from lines and payments.
- **C13** Important mutations create audit records. Histories have read/filter/detail interfaces, not arbitrary edit/delete controls. Dashboards present derived information and links to dedicated work pages.

## OPEN business decisions (carried from the legacy prototype)

These remain unresolved and are not made definitive by this prototype:

1. **O1** Simultaneous assignment of one supervisor to multiple SectionShifts: warnings, no final prohibition.
2. **O2** KPI attribution across multiple supervisors on one SectionShift: flagged; ambiguous production components are omitted in the demo.
3. **O3** Employee-code uniqueness tenant-wide versus factory-wide: no final uniqueness constraint imposed.
4. **O4** Approved ProductionDay correction/reopening workflow: history and a policy explanation only.
5. **O5** Self-approval: explicit demo exception acknowledgement, no final authorization rule.
6. **O6** Simple quality inputs versus detailed quality taxonomy: only the requested simple inputs.
7. **O7** Final QCO business meaning/source: optional reading, no invented source system.
8. **O8** Tenant-wide versus factory-specific style identity: factory reference exists; no final style-number uniqueness policy.
9. **O9** BuyerOrderLine SKU/size/colour variants: visibly future scope, not modeled.
10. **O10** BOM/MRP scope: excluded.
11. **O11** Attendance correction approval policy: immediate demo correction with history, governance pending.
12. **O12** Multiple attendance segments per day/shift: one demo register row per employee/date/shift; no segmented attendance model.
13. **O13** Score configuration governance and approval: editable authorized demo config, immutable snapshots; final approval policy pending.
14. **O14** Organization-scope inheritance/precedence: explicit demo scope selector, final combinations/precedence pending.
15. **O15** RFQ, supplier PO, GRN and invoice number uniqueness: no final tenant/factory/supplier-wide uniqueness rules.

## Intentionally not implemented (carried from the legacy prototype)

Real authentication/authorization, server APIs, RLS, database constraints, production accounting/payment execution, payroll, GL, BOM/MRP, individual sewing-operator skills, operation-level balancing, detailed unapproved quality classifications, size/colour/SKU architecture, real machine/IoT calls, email/SMS, object/file storage, schema-per-tenant controls, microservices, background workers and production deployment.

The prototype is not a final production schema, authorization engine or accounting system. The existing production scaffold remains unchanged apart from a documentation link.
